①為什麼要「重訓」而非後處理

第一人稱看到的雲霧＝針狀低透明高斯，跟銳利桌邊／牆面是同類異向高斯（本場景長寬比中位 13.6、75% 是針）。所以後處理兩難：夾全部會糊、刪太多會破洞。研究一致結論（StableGS／DRGSplat／Lund-LiDAR 2026）：訓練時加深度約束，把高斯壓回真實表面 → 雲霧根本不長。順便把網頁版被 -H 0 剝掉的 SH 重新訓回來，Blender／KIRI 才能正常渲染、可重光。

③環境踩坑（最有價值的紀錄）

Colab 現在的映像是 torch 2.11.0+cu128（超新，gsplat 無對應預編 wheel）。先用 pip install gsplat --no-build-isolation 從源碼編成功，接著跑官方 simple_trainer.py 卻一個接一個缺套件／版本不合——逐一排掉才跑得起來：

#報錯根因解法
1No module named 'tyro'整包 requirements.txt 裡有要編譯的套件，build 失敗就全部 rollback，tyro 也沒裝成別裝整包；只裝純 Python 輪子：tyro nerfview viser tqdm imageio tensorboard torchmetrics plyfile
2gsplat.color_correctPyPI sdist 漏打包此子模組；只用在 eval 的色彩校正，不影響訓練/輸出寫一個 identity stub 模組頂掉它
3datasets.colmapexamples 的 datasets/ 沒有 __init__.py，被 Colab 預裝的 HuggingFace datasets 套件搶先 importtouch datasets/__init__.py → 變正規 package，cwd 最前 → 本地版勝出
4No module named 'pycolmap'要的是 rmbrualla 的純 Python pycolmap（有 SceneManager），不是官方綁定pip install git+rmbrualla/pycolmap@cc7ea4b
4bOverflowError … uint64該套件寫 np.uint64(-1)，NumPy 2.0 不再把負數環繞成無號數patch 成 np.uint64(2**64-1)
5No module named 'fused_ssim'SSIM loss 的 fused CUDA kernel（硬 import）pip install git+rahul-goel/fused-ssim --no-build-isolation（編 ~1.5 分）
6No module named 'splines'nerfview 互動 viewer 的依賴pip install splines ＋ 訓練加 --disable-viewer
✓ 教訓：先跑 200 步 smoke test 把這串 import 一次掃完（gsplat 首次 JIT 編 CUDA 約 189 秒、編完會 cache），再開 30000 步正式跑——省得等 40 分鐘才在第 0 步炸。卡關報錯時也可按 Colab 的「說明錯誤」叫 Gemini 給提示，多一個 AI 視角再自行驗證。

⑤成效判讀（誠實版）

下面是保留的新視角（held-out）渲染——左：原始照片（GT）／右：模型預測。這是檢驗「學得準不準」最公正的方式。

左 GT 銳利／右 預測很糊：窗框、黑板位置都對，但細節被抹掉
另一視角：結構認得出，整體偏軟
少數 pose（落在覆蓋不足區）預測幾乎全黑
自動環繞影片：橢圓路徑會穿過低覆蓋區 → 糊白／黑，不適合當展示

根因

  • 輸入解析度只有 1200×900（COLMAP 沿用 800px 預縮放版），遠低於現有 8K Brush 版——這是糊的主因。
  • 深度正則把高斯壓到表面（去霧有效），但也犧牲一點銳利度。
  • 360 衍生的相機 pose 在部分區域不準＋視角覆蓋稀疏 → 新視角破綻大。

⑥中段判讀（1200px 版）

✓ 達成：去霧成功（無飄絲）·SH 練回來（可重光）·深度正則管線在 Colab 跑通並完整記錄。
✗ 但 1200px as-is 不行：更糊、PSNR 18、少數視角全黑（見上方 ⑤）→ 直接拿這版上站會是降級。但根因是輸入解析度太低，不是管線。
💡 假說：把輸入解析度拉高、再修各幀曝光不一致，應該就能「又去霧又清晰」。於是又跑了一版 ⏷

⑦翻盤：1600px + bilateral grid 可上站

同一套深度正則管線，兩個改動：(1) 輸入解析度 1200→1600px（改用 homeec-stitched 那套 COLMAP）；(2) 開 --use-bilateral-grid，校正 360 衍生各幀的曝光／白平衡不一致（這是 Brush 做不到、gsplat 才有的）。結果直接翻盤：

✓ 結論：1600px + bilateral grid 是可上站品質，同時保 SH（餵 Blender/KIRI 重光）＋去霧（深度正則）。LPIPS 砍半最關鍵——感知清晰度約 2× 提升。教訓：低解析度不是管線的錯，拉高輸入＋修曝光就能贏。

交付：含 SH 壓縮模型（143MB，給 Blender/KIRI）＋去 SH web 版（38MB，2.44M 高斯）。本實驗證明深度正則 + SH 管線在足夠解析度下能產出可部署成果。
